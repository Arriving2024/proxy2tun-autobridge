## 历史手工 DNS 恢复记录

以下是用户提供并确认恢复的摘要，**不是 v0.2.1 通用封装的实测结果**。

| 顺序 | 观察 | 能支持的结论 |
| --- | --- | --- |
| 1 | 经 `socks5h` 请求公开 ChatGPT 站点，约 0.4 秒收到带 challenge 标记的 HTTP 403 | 远端解析的代理 HTTPS 通道可达；服务要求 challenge，不能把它当成断网或登录成功 |
| 2 | 同一入口使用 `socks5` 本地解析时 DNS timeout | 本地 DNS 路径有故障；本地代理能通不证明系统 DNS 可用 |
| 3 | 旧 TUN 请求为 HTTP 000 / reset | 核心存在不等于数据转发健康 |
| 4 | 候选配置通过核心检查，重建 TUN，启用 DNS hijack 和经本地代理 detour 的加密 DoH | 这是当时采用的修复组合；仅凭配置检查不能宣称恢复 |
| 5 | 重建后系统 A 记录解析成功，HTTPS 收到 403 | 该次系统解析和 HTTPS 传输恢复，应用访问仍须单独验证 |
| 6 | 用户确认远控恢复 | 支持用户当时使用中的远控场景；不代表所有协议或新封装都已验证 |

通用配置根据检测结果生成 SOCKS5 / HTTP `upstream` 出站，不固定到历史客户端名称或端口。发行过程不导入、改写或打包旧客户端/手工 TUN 配置。

## 自动化检查范围

下面是本次候选应覆盖的检查范围。实际通过与否以**当前提交**的测试输出和 CI 为准，不用旧版或本机 legacy 修复包的断言数量代替。合成代理、模拟网卡/核心及隔离安装检查不创建真实 TUN，也不改变当前路由。

| 检查 | 范围与必要回归 |
| --- | --- |
| PowerShell 5.1 语法与编码 | ps1/psm1 为 ASCII 或有效 UTF-8 BOM；拒绝无 BOM 非 ASCII；中文路径、离线编码修复和兼容停止入口 |
| 代理发现 | SOCKS5 / HTTP CONNECT、分段响应、超时、明确入口只检测指定目标；元数据未知、重复记录和实际连接所有者核验；不得靠进程同名推断归属 |
| DNS / 路由配置 | hijack、DoH 地址/SNI/path、动态出站、默认无共享 DNS 直连、显式引导兼容选项、回环排除与规则顺序 |
| DNS 响应解析 | 正常 A、SOA 支撑的 NXDOMAIN / NODATA；事务、问题、类、长度、截断及来源检查；拒绝无 SOA、无关区域、错误类/段、SERVFAIL；自行生成问题的真实 NODATA 报文离线回归 |
| 路由健康 | 正确网卡 GUID/状态；按前缀严格并集覆盖要求的 IPv4 / IPv6 非回环范围；默认路由、两条 `/1` 与更多拆分前缀；删除必要段后必须拒绝 |
| HTTPS 与进程边界 | 证书校验、204 / 401 / challenge 403 / 服务错误与传输错误区分；保留原生空参数；关闭环境代理与 curl 配置干扰；限时及子进程清理 |
| 配置事务 | 官方校验前不替换；保留旧字节；原子切换；失败回滚；首启撤销；活动配置或备份被外部修改后拒绝覆盖 |
| 生命周期 / Watch / Stop | 等待、启动、失联、出口变化、防抖、恢复预算与退避、持续健康后重置、暂停恢复；只停止本安装拥有的进程/网卡，保留无关实例 |
| 安装与卸载 | 隔离目录、归属清单、已有目录/越界/链接拒绝、保留未知文件、可选清除数据；默认无开机任务 |
| 官方核心兼容 | 固定官方 sing-box 1.14.2 对 SOCKS5 / HTTP 生成配置执行 `check`；不把语法检查当作转发验收 |
| 发行包 | Git 跟踪源码白名单、编码、最终 ZIP 逐文件 SHA-256、清单与外部校验和；排除 runtime、私人数据和第三方二进制 |

## 复现自动化检查与构建

在源码目录的系统 Windows PowerShell 5.1 中执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\Test-All.ps1
```

包含官方配置和隔离安装/卸载检查时，使用从官方取得、且由安装/构建流程校验过的固定核心。以下仅为示例路径：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\Test-All.ps1 -SingBoxPath 'C:\Tools\sing-box.exe'
```

预期是全部请求的检查输出 PASS，并明确提示没有创建 TUN。任何失败都应先处理，不能用历史输出替代。进程测试可能打印一次性测试子进程的 CTRL_BREAK 提示；测试负责限时清理。

新增发行源码必须已纳入 Git 跟踪，输出目录不能存在同名发行文件：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\Build-Release.ps1 -Version v0.2.1 -OutputDirectory 'C:\ReleaseOutput\v0.2.1'
Get-FileHash 'C:\ReleaseOutput\v0.2.1\Proxy2TUN-AutoBridge-v0.2.1-windows-x64-source.zip' -Algorithm SHA256
```

测试、构建和发布是不同步骤。记录被测提交、运行环境、构建清单与发布产物校验结果；实际发布状态以对应 GitHub Release 为准，不把本地 ZIP 当作已经发布。最终 CI 也不能补齐未执行的管理员实机验收。

## 通用 v0.2.1 管理员实机清单

以下项目不能用朋友的手动 preview 或本机 legacy 启动器结果勾选。应在能本地操作和恢复的设备上，对**本次构建的通用安装包**逐项执行并留下脱敏结果；不要为了验证而叠加第二个 TUN 或覆盖仍正常使用的手工配置。

- [ ] 记录起始状态、版本与恢复入口；通过各自工具正常停止其他 TUN。
- [ ] 从本次构建安装到独立目录，确认 Detect / Generate 选择实际代理核心，明确入口时没有探测无关端口；重新测量耗时。
- [ ] 管理员启动通用 Watch，核验专用网卡身份、完整非回环路由覆盖、新查询 DNS、系统 DNS 与 HTTPS；不能只看进程和网卡 Up。
- [ ] 在 ChatGPT 或目标应用中完成一次真实操作并确认结果；将应用成功与匿名 API 401 / challenge 403 分开记录。
- [ ] 切换 Wi-Fi / 以太网，短暂断开并恢复网络，核对防抖、退避和有限恢复，同时检查其他应用访问。
- [ ] 退出及重启代理客户端，验证真实端口/所有者变化；关闭窗口但进程仍在托盘时不能误认为客户端退出。
- [ ] 在可恢复条件下验证“核心活着但转发失败”，确认连续失败阈值、预算耗尽、释放归属 TUN 与 `RecoveryPaused`，没有无限重建。
- [ ] 验证正常停止、关闭前台窗口与紧急停止；只撤销本实例资源，原代理客户端仍可独立使用。
- [ ] 验证卸载、配置回滚及回退旧安装；不混用不同版本的 runtime、归属清单或进程信息。
- [ ] 对 IPv6、不同代理客户端、复杂进程树和含中文路径的安装分别记录结果，不从某台设备的 IPv4 成功外推。
