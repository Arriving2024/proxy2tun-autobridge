# 故障排查

## 没有发现代理

先启动原有客户端，并确认它确实暴露本机 SOCKS5 或 HTTP CONNECT 端口。只有远程 VPN 连接、PAC 地址或需要认证的代理，不属于 v0.1.0 自动适配范围。执行 `Start-Bridge.ps1 -Mode Detect` 查看候选信息；也可用 `-ProxyEndpoint 'socks5://127.0.0.1:10808'` 指定实际端口。

探测会通过代理向 `1.1.1.1:443` 发起有限的连接/TLS 探测。该目标被客户端规则或所在网络屏蔽时，即便代理在其他目标可用，也可能被判定不可用。监听端口归属进程的路径无法读取时，可在管理员窗口再次探测；不要用不相关的进程路径冒充上游核心。

## 启动时要求管理员权限

TUN 需要权限创建虚拟网卡和路由。右键 `Start-Bridge.cmd` 选择“以管理员身份运行”，或自己打开“Windows PowerShell（管理员）”。启动脚本不自动弹出 UAC，普通双击不等同于管理员启动。安装器通常不需要管理员权限，不会静默提升权限或添加常驻服务。`Detect` 与 `Generate` 不开启 TUN。

若 UAC 使用另一个管理员账号，Windows System Proxy 属于那个账号，可能和原账号不同。此时用 `-ProxyEndpoint` 明确指定原客户端的本地端口，并检查生成的进程路径。

## 提示已有 sing-box 或其他 TUN

先在原客户端正常关闭原有 TUN，再启动 AutoBridge。v0.1.0 不接管、不结束已有 sing-box 实例。发布验证环境中的手动 sing-box 也不应为了检查本工具而被强行终止。不要把一个已经有 TUN 的系统叠加成多个相互捕获的默认路由。

## 开启后网页打不开，日志反复重连

1. 在管理员窗口执行 `Stop-Bridge.ps1 -Emergency`，先恢复普通网络。
2. 确认原客户端在没有 AutoBridge 时仍可通过本地代理访问网络。
3. 检查 Detect 显示的监听进程、程序路径、父进程是否对应实际客户端。
4. 若监听进程把连接交给另一个独立核心，用 `-ExtraDirectProcessPath` 增加那个核心的完整路径。
5. 检查客户端是否刚升级或更改端口，并重新启动 Watch 让进程身份重新识别。

不要把所有进程设为 DIRECT 来“修复”回环，这会使接管失去意义。也不要手动删除系统默认路由或所有 Wintun 网卡。

## 网页能用，但游戏、远程控制或视频软件不能用

本版不转发一般 UDP、QUIC 或 ICMP。应用必须支持 TCP 回退才可能可用。`ping` 失败不能单独证明代理连接失败。Misty 的历史手动方案成功，不代表所有 UDP 型远控产品都兼容这份保守的 v0.1.0 配置。

## DNS 或隐私测试显示直连

本版允许 Windows DNS Client 经正常网络解析，目的是避免上游核心首次解析服务器域名时进入回环。`dns_mode` 为 `disabled`，`strict_route` 为 `false`。因此没有 DNS 泄漏保护，也没有 kill switch；请勿把界面的 ACTIVE / TUN 已启动理解为全部流量的隐私保证。

## 上游客户端退出后发生什么

Watch 默认每 3 秒检查一次，连续 2 次失败后撤销自己启动的 TUN。探测本身也有超时，实际恢复时间会更长，并非严格的 6 秒承诺。之后继续等待可用上游；端口重新出现并通过验证后可再次启动。窗口停止或关闭后不在后台持续自动运行。

## 紧急停止或断电后网络异常

在安装目录打开管理员 PowerShell，执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Stop-Bridge.ps1 -Emergency
```

该命令依赖运行状态与实例身份核验，只处理本工具的进程与专用适配器。若状态无法核验，它会保守拒绝；保留 `runtime\` 供排查，不要为了绕过校验手工修改 PID。可重启 Windows 让失效的会话和临时路由清理，再单独检查原客户端是否正常。不要执行网上的“清空全部路由/杀掉所有 sing-box”一键修复。

进程保护能覆盖普通窗口退出和子进程终止场景，但不能保证断电、系统崩溃、驱动故障时立刻完成所有用户态清理。具体已验证的边界见 [验证记录](validation.md)。

## 安装下载失败或校验失败

下载仅使用 [sing-box 官方 Release](https://github.com/SagerNet/sing-box/releases/tag/v1.14.2)。校验失败时安装器不会执行下载的文件；重新下载或自行提供官方 Windows amd64 1.14.2 的 `sing-box.exe`。不要跳过固定 SHA-256 验证，也不要从陌生镜像复制同名二进制文件。

`-SingBoxPath` 使用用户自己提供的本地执行文件，来源由用户确认；安装器仍检查其版本与架构。只有网络请求会受原有 Windows 代理设置影响，安装器不会修改设置来绕过网络限制。

## 卸载拒绝目录，或保留了文件

卸载器只接受 `install.ps1` 建立并记录的目录。源代码下载目录没有安装归属清单，不能交给卸载器。安装目录被移动、清单被改写、包含目录联接/符号链接，或停止脚本被修改时，会拒绝删除并报告原因。

默认保留 `runtime\`。需要同时清理日志时，第一次卸载就加 `-PurgeData`。未知文件不属于本工具，卸载后仍会保留。共享 Wintun 驱动包也会保留，避免影响其他 VPN 客户端。

## 提交问题时附什么

说明 Windows 版本、sing-box 版本、原客户端名称、Detect 是否发现端口、错误发生在安装/生成/启动/运行/停止的哪一步，并附已遮盖个人路径的相关日志。核心日志也可能包含访问目标域名/IP，请按需遮盖。不要上传订阅 URL、远程节点信息、账号密码、私钥或原客户端配置文件。请把历史手动成功、自动化基础检查与管理员实机 TUN 测试分开描述。
